synthetic-exif6.heic — provenance
==================================

Generated by scripts/make-heic-exif-only-fixture.py for fauxcasa-zq9
(HEIC/HEIF: EXIF-only rotation, no container irot/imir). Rerun the
script to regenerate; `--check` verifies the committed bytes match a
fresh build.

This is a SYNTHETIC file — no real camera, no personal data.

The "EXIF-only shape": a real EXIF Orientation=6 tag and NO `irot`/
`imir` item property in the container. Uncommon in the wild (most
encoders, Apple's included, write both — see synthetic-rot6.heic.txt
for that shape), but legal, and before fauxcasa-zq9 it decoded
SIDEWAYS: libheif had no container transform to apply, and pi-heif's
opener had already reset the EXIF tag to 1, so no orientation signal
survived to pillow_qimage.

Structure:
  - Byte-identical to synthetic.heic (96x64 coded plane, four solid
    quadrants: top-left red (220,40,40), top-right green (40,200,60),
    bottom-left blue (40,80,220), bottom-right yellow (230,210,30),
    `ispe` 96x64, item properties hvcC/colr/ispe/pixi only) EXCEPT for
    ONE 2-byte SHORT: the EXIF Orientation value in IFD0 of the
    embedded Exif item, 1 -> 6. Same length, so no iloc/idat offset
    moves. 679 bytes.
  - No `irot`, no `imir` anywhere in `ipco`; `ipma` binds properties
    1-4 (hvcC, colr, ispe, pixi) to primary item 1.

Verified by the generating script on every run:
  - pillowload.heif_container_transform(bytes) is False
  - pi-heif standalone decode is 96x64 (as stored -- nothing rotated)
  - pi-heif in Pillow-plugin mode reports info["original_orientation"]
    == 6 with the live EXIF tag reset to 1
  - metareader.read_orientation (exiv2, raw bytes) reports 6 -- this is
    the value pillowload.heic_manual_orientation applies (not pi-heif's,
    which may be XMP-sourced; see synthetic-xmp6.heic.txt)

Expected display after the fauxcasa-zq9 fix: 64x96, quadrants rotated
exactly as synthetic-rot6.heic's — displayed top-left is the stored
bottom-left (blue), top-right is stored top-left (red), bottom-left is
stored bottom-right (yellow), bottom-right is stored top-right (green).
The two fixtures are the same photo carrying its rotation two different
ways, and pillow_qimage must render them identically.
